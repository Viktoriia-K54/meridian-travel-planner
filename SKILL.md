# MERIDIAN — планировщик путешествий

Полное руководство по проекту: архитектура, модель данных, логика подбора, правила
разработки и проверки. Перед изменениями прочитай этот файл целиком.

## 1. Что это за проект

Интерактивная презентация-планировщик на чистом HTML/CSS/JS:

1. Опросник из 13 вопросов. Первый — про страну: конкретная страна или свободный подбор.
2. Профиль путешественника с возможностью изменить любой блок и добавить историю поездок.
3. Подборка из 3–5 направлений с процентом совпадения и объяснением.
4. Детальный маршрут выбранного направления: дни, бюджет, логистика, жильё,
   чек-лист бронирований, вещи, риски.
5. Выбор варианта, печать / сохранение в PDF.

В каталоге 29 направлений: Россия (17), Грузия, Армения, Азербайджан,
Турция, Италия, Исландия, Марокко, Таиланд, Португалия, Норвегия, Япония, Шри-Ланка.

## 4. Архитектура

- Один HTML-файл, четыре CSS-файла, классические `<script>` без модулей.
- Порядок подключения скриптов в `index.html` важен: сначала `meta.js`, затем
  `questions.js`, `destinations.js`, четыре файла `itineraries-*.js`, потом
  `ui.js` → `matcher.js` → `storage.js` → `views/shared.js` → views → `app.js`.
- SPA-состояние: `intro → quiz → summary → results → detail`.
- Состояние хранится в `localStorage` под ключом `meridian.travel.v1`;
  при недоступности хранилища работает запас в памяти вкладки.
- Роутинг через hash + `history.pushState`:
  - `#/quiz/N`
  - `#/summary`
  - `#/results`
  - `#/trip/<destinationId>`

### Состояние приложения

```js
{
  screen: 'intro' | 'quiz' | 'summary' | 'results' | 'detail',
  qIndex: 0,
  answers: { ... },
  results: null | { items, total, strictCount, relaxed, empty, visitedAvoided },
  chosenId: null,
  checks: {},           // отметки чек-листа по id направления
  detailId: null,
  instant: false,       // true отключает анимацию перехода
  hasProgress: false
}
```

### Ответы (`answers`)

```js
{
  country: { mode: 'chosen' | 'open' | null, id: 'Россия' | null },
  visited: [{ id, place, route }],          // до 20 записей
  party: { id },
  dates: { mode: 'exact' | 'season' | 'flex' | null, dateFrom, dateTo, season, nudge },
  duration: { value, flex },
  budget: { value, flex },
  restTypes: ['beach', ...],                // до 3
  pace: { id, flex },
  comfort: { hotel: '3' | '4' | '5' | 'boutique', flight: 'economy' | 'comfort' | 'business', flex },
  transfers: { id, flex },
  visa: { id },
  climate: { id },
  interests: ['food', ...],                 // до 3
  constraints: { items: ['none' | 'mobility' | ...], dream: '' }
}
```

`emptyAnswers()`, `hydrateAnswers()` и `hasProgress()` живут в `assets/js/app.js`.
При добавлении поля обновляй все три.

## 6. Модель данных

### Направление (`TravelApp.destinations[]`)

```js
{
  id: 'georgia',                 // уникальный, используется в маршрутах и роутах
  country: 'Грузия',             // точное название; по нему работает фильтр страны
  place: 'Тбилиси · Кахетия · Казбеги',
  title: '...',                  // заголовок карточки
  tagline: '...',
  image: 'assets/img/georgia.jpg',
  region: 'Кавказ',
  types: ['culture', 'food', 'nature'],
  difficulty: 2,                 // 1–5
  pace: 'balanced',
  days: [7, 10],                 // рекомендуемый диапазон
  months: [4, 5, 6, 7, 8, 9, 10],
  climate: 'mild',               // warm | mild | cool
  flight: { hours: 3.5, direct: true, note: '...' },
  visa: 'none',                  // none | evisa | required
  visaHint: '...',
  comfort: [3, 4, 5],            // допустимые уровни отеля
  family: true,
  party: ['alone', 'couple', 'family', 'friends'],
  interests: ['food', 'history', 'photo', 'local', 'silence'],
  highlights: ['...'],           // используется и в UI, и при распознавании истории
  budgetParts: {
    flights: [min, max],
    stay: [min, max],
    food: [min, max],
    transport: [min, max],
    activities: [min, max],
    buffer: [min, max]
  }
}
```

### Маршрут (`TravelApp.itineraries[id]`)

```js
{
  recommendedDays: 9,
  paceNote: '...',
  days: [{ title, place, items: ['...'] }],
  trim: '...',                   // что убрать / добавить при другой длительности
  stay: [{ area, note }],
  transport: '...',
  booking: ['...'],              // минимум 3 пункта
  packing: ['...'],              // минимум 2 пункта
  risks: [{ title, text }]       // минимум 1
}
```

Инварианты, которые проверяет `smoke_test.js`: у каждого направления есть маршрут,
в маршруте ≥3 дней, у каждого дня есть `title`, `place`, непустой `items`,
≥1 вариант жилья, ≥3 пункта бронирования, ≥2 пункта вещей, ≥1 риск,
все шесть статей бюджета на месте, файл изображения существует.

### Вопрос (`TravelApp.questions[]`)

Поля: `id`, `block` (индекс блока), `kind`, `title`, `subtitle`, `hint`, `required`.
Типы `kind`:

- `country` — режимы `chosen` / `open` и динамическая сетка стран;
- `single` — один вариант из `options`;
- `multi` — до `max` вариантов;
- `dates` — режимы `exact` / `season` / `flex`;
- `duration` и `budget` — диапазоны;
- `comfort` — отель + класс перелёта;
- `constraints` — мультивыбор + свободный текст мечты.

Гибкость параметра задаётся объектом `flex: { default, offLabel, onLabel, note }`.

## 7. Логика подбора (`assets/js/matcher.js`)

Порядок работы:

1. **Страна — жёсткий фильтр.** Если `answers.country.mode === 'chosen'`,
   в выборку попадают только направления этой страны. Мягкий режим тоже не выходит за неё.
2. **Жёсткие фильтры:**
   - виза: `none` отсекает всё, кроме безвизовых; `evisa` — всё, кроме `required`;
   - семья с детьми: только `family: true` и сложность ≤3;
   - бюджет: `totals.min > budget * ceiling` отсекается
     (`ceiling = 1.15` при гибком бюджете, в мягком режиме — `max(1.35, stretch)`);
   - фиксированная длительность вне `days` — отсекается (кроме мягкого режима);
   - «только прямой» при жёстких пересадках — отсекается (кроме мягкого режима).
3. **Скоринг.** База 35, максимум 155:
   - бюджет +10 / +7 / +2;
   - виза +3 / +1;
   - компания +5;
   - длительность +6 (гибко) или +8 (фиксированно);
   - сезон +8, вне сезона −18 при жёстких точных датах, иначе −8;
   - гибкие даты +4;
   - формат отдыха: до +42 (14 за совпадение, минус 14 при полном промахе);
   - темп: до +12, плюс +2 при гибкости;
   - климат +8 / +4 / −4;
   - акценты: до +12;
   - перелёт: +8 / +6 / +3;
   - комфорт: ±6;
   - ограничения: штрафы;
   - посещённое место: −20.
4. **Процент совпадения** = score / 155, ограничен 52–98%.
5. **Выбор вариантов:** топ-4 по score + пятый «Свежий взгляд» с другим основным типом.
   Пятый показывается только если в пуле есть кандидат.
6. **Мягкий режим** включается, если строгих совпадений меньше трёх.
   Новые варианты помечаются `compromise: true` («Ближайший вариант»).
7. **История поездок:** направления из `visited` получают `visited: true` и штраф −20.
   Если свежих альтернатив ≥3, посещённые не показываются (`visitedAvoided`).
   Если свежих меньше трёх, они возвращаются в подборку со значком «Вы уже были».

### Распознавание истории

`isVisited()` нормализует регистр, `ё → е`, убирает пунктуацию и сравнивает:

- полное совпадение места со страной (например, «Грузия» → все направления Грузии);
- вхождение нормализованного места в `country`, `place`, `title`, `tagline`, `highlights`;
- для многословных мест — совпадение ≥60% слов (минимум 2);
- фрагменты маршрута, разделённые `— – → , ; /`.

## 8. Соглашения по интерфейсу

- Шрифты: Cormorant Garamond (заголовки) + Inter (текст).
- Палитра: слоновая кость, чернильный, зелёный, терракота, золото.
  Токены — в `assets/css/base.css`.
- Все действия — через `data-action` и делегированный обработчик в `app.js`.
  Новое действие добавляй в объект `actions`.
- Ответы сохраняются через `setAnswer(questionId, value)`; затем `instant()`
  для мгновенного перерисовывания без прокрутки или `navigate()` для перехода.
- Пользовательский текст — всегда `ui.escapeHtml`.
- Доступность: семантические кнопки, `aria-pressed` / `aria-checked`,
  видимый фокус, стрелки ←/→ в опроснике, `prefers-reduced-motion`, skip-link.
- Печать: отдельные правила в `detail.css`.

## 9. Как добавить направление

1. Добавь объект в `assets/js/data/destinations.js` со всеми полями.
   `id` — латиницей, уникальный.
2. Добавь маршрут в подходящий `itineraries-*.js`. Если создаёшь новый файл —
   подключи его в `index.html` **и** добавь в массив `FILES` в `scripts/smoke_test.js`.
3. Положи фото в `assets/img/<id>.jpg` и добавь строку в `assets/img/CREDITS.md`:
   автор, лицензия, ссылка на исходный файл Wikimedia Commons.
4. Проверь, что бюджет собран из шести статей, а маршрут проходит инварианты.
5. Запусти `node scripts/smoke_test.js` и `node scripts/e2e_test.js`.

Страна автоматически появится в сетке первого вопроса и в фильтре.

## 10. Как изменить опросник

При добавлении или перестановке вопросов обнови:

1. `TravelApp.questions` и при необходимости `TravelApp.blocks`;
2. `TravelApp.ui.isAnswered` — правило «ответ дан»;
3. `controlFor()` в `views/questionnaire.js` — рендер контрола;
4. `emptyAnswers()` и `hydrateAnswers()` в `app.js`;
5. **жёстко заданные индексы редактирования**:
   - `views/summary.js` — `group('Контекст', 0, ...)`, `4`, `7`, `10`;
   - `views/results.js` — пустое состояние, `data-index` у кнопок.
6. тесты: `makeAnswers()` и сценарий `e2e_test.js`.

Не забывай: количество вопросов выводится динамически, но тексты в intro,
meta description и тестах могут содержать число явно.

## 11. Проверки

Из папки проекта:

```bash
node scripts/smoke_test.js          # данные, подбор, рендер всех экранов
node scripts/e2e_test.js            # сквозной сценарий в headless Chrome
VIEWPORT=390x844 node scripts/e2e_test.js
node scripts/capture_screenshots.js # обновить screenshots/*.png
```

`smoke_test.js` загружает скрипты в `vm`, проверяет каталог, маршруты, подбор
на пяти профилях, фильтр страны, историю поездок и рендер экранов.
`e2e_test.js` проходит реальный сценарий: страна → 13 вопросов → профиль с историей →
подборка → детальный маршрут → чек-лист → выбор варианта.
Скриншоты сохраняются в `screenshots/`.

## 12. Подводные камни

- `#app` не существует; корень приложения — `<main id="main">`.
- Одиночные ответы иногда приходят строкой из старого localStorage —
  используй `normalizeIdAnswer()`.
- `country` в старом сохранении может быть строкой; `hydrateAnswers()` обязан это пережить.
- `saved.pace` / `transfers` / `visa` / `climate` могут быть `null` — спред безопасен,
  но проверяй итоговую форму.
- Пятый вариант добавляется только при наличии пула; не рассчитывай всегда на 5 карточек.
- При выбранной стране подборка может быть короче 3–5 — это ожидаемо,
  интерфейс должен честно объяснять причину.
- Посещённые направления нельзя исключать жёстко: при нехватке свежих альтернатив
  они возвращаются с бейджем.
- Новый JS-файл без подключения в `index.html` и в `FILES` теста молча не заработает.
- Изображения — только с корректной атрибуцией в `CREDITS.md`.
